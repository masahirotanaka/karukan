# 「ん」の打ち忘れ補正

`ん` は 2打鍵（`nn`）を要する唯一のかなです。1回で済ませてしまうと別のかなになり、
気づかないまま変換されます。Karukan はこれを2段構えで扱います。

## 末尾の `n` は `ん` になる

語末の `n` は、それ以上ルールが伸びないので確定時に `ん` になります。

```
nihon   →  にほん
kan     →  かん
karukan →  かるかん
```

以前は literal な `n` のまま確定していました（`にほn`）。他の日本語IMEと同じ挙動に揃えています。

入力途中の `n` は待機したままなので、`na`・`nya` は従来どおりです。`ny` のまま確定した場合は
`んy`（`n` が確定し `y` はそのまま）になります。

## 途中の `n` はモデルの確信度で直す

語中の `ん` は機械的には確定できません。`かに` と `かんい` はどちらも正しい日本語だからです。
そこで Space で変換したとき、**`n` を1つ足した読み**でも変換し、**どちらがモデルにとって
尤もらしいか**を比べます。

```
sinyabasuninoritai  →  深夜バスに乗りたい     ← 差し替え（打っている最中から）
kaniwotaberu        →  カニを食べる          ← 差し替えない（簡易を食べる は2番目）
```

補正はかなのパターン表ではなく**打鍵そのもの**に対して行います。`n` を1つ挿入して変換し直すだけで、
母音の前（`kanni`）・な行の前（`konnni`）・や行の前（`shinnya`）のすべてを1つのルールで拾えます。

### どう判定しているか

「打った通りの読み → その変換結果」と「直した読み → その変換結果」を、どちらも**1文字あたりの
負の対数尤度（NLL）**で採点します。モデル自身が出した2つの変換を比べているので、変換と当てずっぽうを
比べることにはなりません。比較は差ではなく**比**で行います。自信のある読みと無理に通した読みとでは
NLL が桁で違うためです。

| 比（打った通り ÷ 直した後） | 扱い |
|---|---|
| 3倍以上 | **差し替える**（先頭に出す） |
| 1/3 〜 3倍 | 「もしかして」候補として並べる |
| 1/3 以下 | **捨てる**（モデルは打った通りのほうを確信している） |

jinen-v2-small で19読みを実測した値です。本当に `n` を落としていた読みは 3.5〜3800倍、
正しく打てている読みは 1.5倍以下に収まり、間に十分な隙間があります。低すぎる閾値は打った文章を
黙って書き換えるので、迷ったらこの数値は上げる側に倒します。

### 安全装置

- **「ん」で始まる補正は捨てます。** 日本語に「ん」で始まる語はありません。
  `nekogasukidesu` を直すと「んえこがすきです」になり、モデルはこれを「猫が好きです」より
  高く評価してしまいます（実測）。この除外がないと「猫が好きです」が化けます。
- **5文字未満の読みは差し替えません。** 2〜3かなではスコアに意味がありません。
  `かに` が `かんい` より悪く出るのは、単に「蟹」が「簡易」より珍しいからです。
  短い語は打ち直すほうが速いので、候補として出すだけにします。
- **モデルが無い・採点に失敗したときは差し替えません。** 判断がつかないときは打った通りを守ります。
- **1回の変換につき採点するのは最初の補正だけ**です。採点は1回につき2パス走ります。
  2つ目の補正が正解になるような読みは、もう「1打鍵の取りこぼし」ではありません。
- **ローマ字が途中の打鍵では判定しません。** `sinyabasunin` の時点では、読みは
  「しにゃばすに」でも打鍵には `n` が1つ余っています。この状態で補正を作ると、
  別の読みの変換と比べることになってしまいます。

### そのほかの仕様

- **1回の変換につき補正は最大2つ**まで試します。`n` の数だけ推論が走るのを防ぐためです。
- **打った通りの読みと同じ結果になる補正は出ません。** 直すところがない語のコストはゼロです。
- **確定すると「打った通りの読み」で学習します。** `かに` → `かんい` が記録されるので、
  同じ打ち間違いを次にしたときは 📝学習 の候補として即座に出ます。打ち間違いを覚えさせて
  実用上の手数を減らすのが狙いです。不要なら変換中に Ctrl+Backspace で履歴から消せます。
- **ライブ変換（入力中の表示）にも効きます。** 打っている最中から正しい表示になり、
  そのまま Enter で確定できます。追加コストは1打鍵あたり +11〜37ms（実測。ローマ字が
  途中の打鍵と5文字未満はそもそも判定しないので、その分は0です）。
- 差し替えが不要なら `config.toml` で切れます。候補としては従来どおり出ます。

```toml
[conversion]
auto_correct_n = false
```

### 実測されている限界

- **1打鍵の取りこぼししか直せません。** `n` を2つ以上落とした読みは対象外です。
- **`n` を丸ごと落とした場合は直せません。** `benkyou`（べんきょう）を `bekyou`（べきょう）と
  打った場合、足すべき場所に `n` が1つも無いため、このルールでは到達できません。
  直せるのは「`n` を2回打つべきところで1回にした」場合です。
- **取りこぼすことがあります。** `zeninnatsumare`（ぜにんあつまれ）は、モデルが
  「是認集まれ」を「全員集まれ」よりわずかに高く評価するため差し替わりません。
  この場合も補正は候補として出ます。失敗は常に「直さない」側に倒れます。

## `n` を3回打つ場合

`こんにちは` は `konnnichiha`（`n` 3回）です。`ko` + `nn`(ん) + `ni`(に) と分解されるためで、
`nn` を常に `ん` とみなす仕様から来ています。この打ち方自体は変えていません。
打ち忘れたときは上の「もしかして」候補で拾ってください。
